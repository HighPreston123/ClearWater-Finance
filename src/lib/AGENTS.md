## src/lib rules
- Score history reruns the existing `computeHistoricalScore` per complete month; rows are keyed by methodology version + input fingerprint — so recalculation never duplicates and changed data yields a revision.
- The Overview audio summary speaks a script built only from already-computed Overview figures (src/lib/finance/audioSummaryText.ts); `generateAudioSummary` (src/lib/audio.functions.ts) calls ElevenLabs server-side with ELEVENLABS_API_KEY and clips are cached per script — so the key never reaches the browser and unchanged data never re-bills.
- Market data comes only from Alpaca (feed=iex) via src/lib/marketdata.functions.ts → marketdata.server.ts; bars live in hypertable `fin.market_bars` (key symbol+timeframe+feed+ts), latest trades in `fin.market_latest` (also the ~60s cache), watchlists in owner-RLS `fin.watchlist` — so tracked symbols never become holdings and keys stay server-side.
- Read-heavy TigerData endpoints (sign-in load, analytics) use `ownerSnapshot` in src/lib/tiger.server.ts: one simple-protocol script (read-only repeatable-read txn, role fin_app, app.user_id, combined JSON SELECTs, COMMIT) with the validated owner UUID inlined — because with prepare:false each parameterized statement costs an extra describe round trip, and app↔DB latency dominates.
- Read-only server functions may overlap the MFA check with the owner-scoped read via `withMfaRead` (nothing is returned unless MFA passes); writes still call assertMfa before touching data.
- Sign-in bootstrap is one request: `loadSession` returns saved state + onboarding status from one `ownerSnapshot`; the gate and FinanceStore share it via src/lib/onboarding/stateCache.ts, and recordLogin runs only after it finishes — because concurrent per-request DB connections overloaded the published Worker.
