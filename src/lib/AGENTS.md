## src/lib rules
- Score history reruns the existing `computeHistoricalScore` per complete month; rows are keyed by methodology version + input fingerprint — so recalculation never duplicates and changed data yields a revision.
- The Overview audio summary speaks a script built only from already-computed Overview figures (src/lib/finance/audioSummaryText.ts); `generateAudioSummary` (src/lib/audio.functions.ts) calls ElevenLabs server-side with ELEVENLABS_API_KEY and clips are cached per script — so the key never reaches the browser and unchanged data never re-bills.
- Market data comes only from Alpaca (feed=iex) via src/lib/marketdata.functions.ts → marketdata.server.ts; bars live in table `fin_market_bars` (key symbol+timeframe+feed+ts), latest trades in `fin_market_latest` (also the ~60s cache), watchlists in owner-RLS `fin_watchlist`; cache writes use the service-role client server-side only — so tracked symbols never become holdings and keys stay server-side.
- Financial data lives in Lovable Cloud tables `public.fin_*` (migrated from TigerData, which stays untouched as the rollback source). Owner-scoped work uses the caller's client (context.supabase, RLS user_id = auth.uid()); multi-table reads/writes are single SQL functions (fin_read_session, fin_save_state, fin_analytics, fin_record_scores, fin_delete_my_data) — so each request is one atomic, owner-scoped call over HTTPS, which works on the published Worker.
- Read-only server functions may overlap the MFA check with the owner-scoped read via `withMfaRead` (nothing is returned unless MFA passes); writes still call assertMfa before touching data.
